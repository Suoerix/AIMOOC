# 2026-11-23 生产环境故障调研（AI 请求 + 视频播放 500）

## 根因
- 生产 Vercel 函数运行时为旧版 Node（不支持 require(ESM)，即 <20.19 或 18.x）
- commit 89c2803 新增依赖 sanitize-html@^2.18.2 → 其依赖 htmlparser2@12 为 ESM-only
- 所有 import `~/lib/security/input`（引 sanitize-html）的 API 路由模块加载即崩（ERR_REQUIRE_ESM）→ 500
- 受影响：chat/quiz/tts/sumup/courseware/visualize/track/b23tv/bilibili/*/video/*/course/resolve（即全部 AI 与视频接口）
- 不受影响：health/quota/admin-stats/diagnose（不引该模块）；middleware 是 Edge 正常

## 验证方式
- Node 18.20.8 本地跑 next build 产物：完全复现生产症状（500 HTML、health 200、ERR_REQUIRE_ESM 日志）
- Node 20.20.2 / 22.22.2 本地运行全部正常

## 修复（已改代码，待 commit/push）
- package.json 增加 engines: node >=22.12.0（Vercel 依据 engines 选运行时）
- .github/workflows/ci.yml node 20 → 22
- 还需在 Vercel Dashboard → Settings → Build and Deployment 确认 Node.js Version 为 22.x 后重新部署

## 其他发现
- vercel.json regions:["hkg1"] 在 Hobby 计划被忽略，函数实际跑在 fra1（法兰克福），B 站接口修好后建议用 /api/bilibili/diagnose（AIMOOC_ALLOW_DIAGNOSE=1）验证连通性
- aimooc.soerix.cn 对高频探测有约 5s 掐 TLS 的防护（测试 IP 被临时封）；与故障无关

## 【修正】真正的根因 —— 不是 Node 版本，是 Vercel 的 Rust Node 运行时
- Vercel 官方运行时日志（get_runtime_errors, project=aimooc）确认：
  `ERR_REQUIRE_ESM: require() of ES Module /var/task/node_modules/htmlparser2/dist/index.js from .../sanitize-html/index.js not supported`
  堆栈含 `/opt/rust/nodejs.js` → Vercel 的 Rust 重写版 Node 运行时 **不支持 require(ESM)**（即便项目 nodeVersion=22.x）
- count=120，14 条路由全部受影响，first=2026-11-16T08:56（= e871419「升级依赖」上线时刻）
- 因此升级 Node 无效；唯一正解是消除 CJS→ESM 的 require

## 采用的修复（未提交，待用户 push）
- package.json: sanitize-html 钉死 "2.18.2"，新增 overrides: { "htmlparser2": "9.1.0" }（9.x 是最后一个 CJS 主版本，10+ 即 ESM）
- sanitize-html 仅用到 `new htmlparser.Parser({...})`，跨版本稳定 → 覆盖到 v9 安全
- 附带：lib/security/request.ts 新增 isMissingAuthSession()，quota/track 不再把匿名访问记成 ERROR
- 验证：NODE_OPTIONS=--no-experimental-require-module（模拟 Rust Node）下 17 条路由 0 个 500；Node 18 亦通过；37 单测 + typecheck + lint + npm ci --dry-run 全绿
- 关键方法：用 `--no-experimental-require-module` 在本地精确模拟 Vercel Rust Node 的行为
